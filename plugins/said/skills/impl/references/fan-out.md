# impl — Fan-out forms — `arm` and `close`

Read from the spine (`SKILL.md` Step 0 #12) at the moment it names; every rule here is standing for the whole phase.

## Fan-out forms — `arm` and `close`

Two SKILL-level forms let `said:said` fan out a feature's **write-disjoint** tasks (`ADR-SAID-S09`: arms build, main decides). `said:said` spawns them via the Workflow tool, one arm per disjoint task — **never from inside this skill** (a subagent has no Workflow tool). Decisions, gate verdicts, closes and the append-only log stay in main.

### `/said:impl <task-id> arm` — build under **forced autonomy**, decide nothing
Runs Step 0 + Phase A + Phase B under **forced autonomy** — no operator pause (a subagent has no operator, so no STOP is honoured), no task-log write, no commit; a Step 0 #9 HALT (no `## Earned rules`) is returned immediately as the close block, building nothing:
1. **Declaration before write.** The arm's first output, **before any edit**, is the file set it intends to touch, compared to the partition it received from main. A file outside the partition is returned as an **owed item before any edit** — the arm **never widens** its partition.
2. **Decide nothing — return owed items.** Every point the interactive form would STOP (an unsatisfiable Approach at Phase A step 8; a carve-out that turns out to be new behavior; a mid-flight scope classification; an S/M/L escalation to `add-task`; a SOFT-FLAG / soft-finding deferral) is **returned as an owed item, never resolved**. Per-rule `<typecheck>` evidence is one line per rule in the block (not a chat confirmation).
3. **No Phase C.** The arm never runs Phase C (quality gates, `/said:review-ux`, code-review, the close). Those run in main at `close`.
4. **Channel = the return value.** The arm's only output is its schema-validated **close block** (below); it writes **no working-dir artifact** — `said:said` reconstructs the phase from the feature's canonical artifacts (the task log written at `close`), not from an arm file.

**The arm's re-anchor unit.** With no operator there is no confirmation unit, so the arm re-anchors **per Acceptance item** it works: before each `- [ ]` bullet it re-reads the `## Earned rules` section from disk (the rule lines + the counter), echoes `N rules`, and writes the briefing line into its `evidence`; the ids applied per item are returned with the `acceptance` entries. Same rules, same source, one unit = one Acceptance item.

The **close block** the arm returns: `status` (proposed `Done (YYYY-MM-DD)` — main decides + stamps the date), `fix` (one verification line + the `Rules applied:` line), `deviations` / `gotchas` (optional), `refs` (ADR / UX-spec / feature-spec paths created or edited), `acceptance` (per-bullet `[x]` / `[N/A — reason]`), `owed` (decisions returned, not resolved), `files` (declared + actual changed files — scopes the close diff and the partition check), `evidence` (per-rule `<typecheck>` results, test counts). No new `###` headers.

### `/said:impl <task-id> close` — apply in **main**, run Phase C
Runs in **main**. Applies the arm's returned close block (main decides `Status:` and stamps the date), then runs **Phase C** exactly as the interactive form does — quality gates, `/said:review-ux` for every Checker the lane declares (`ADR-SAID-S06` §2), generic code-review with the diff **scoped to the arm's declared `files`** (`git diff -- <files>`; skipped with the logged reason when the lane declares `SAID.code-review: off`), the close-of-task 5-step, the exhaustive close-mutation flip, the summary-table row. The check needs the line on disk: main first writes the block's `fix` (with its `Rules applied:` line) into the task's `### Fix` in the tasks log **without flipping `Status:`**, then runs `python3 ${CLAUDE_SKILL_DIR}/../review-qa/earned-rules.py check --claude-md <lane-root>/CLAUDE.md --task-file <tasks log> --task-id <task-id> --adr-date 2026-09-08` — the same command as the interactive close — and a FAIL is repaired inline in main before the flip, like any other staged FAIL. It checks the arm's **actual diff against its declaration**: a file outside the declaration is an **owed item** (the task does not close clean). A staged FAIL is impl's own "RETURN TO PHASE B", repaired **inline in main once**, then owed — never a second pipeline pass, never a silent revert. Closes are **serial** across tasks — only main writes the append-only log.
